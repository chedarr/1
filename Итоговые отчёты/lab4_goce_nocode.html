Лабораторная работа №4 — многомерный прогноз временного ряда GOCE с помощью LSTM

Цель — предсказать напряжение батареи PHT10180 (BAT_VOL_R) на 24 часа вперёд по 24 часам истории пяти каналов. Главная метрика — MAE (mean absolute error): она измеряет ошибку в тех же единицах, что и напряжение, и не завышается крупными всплесками так, как RMSE.

1. Постановка задачи

Задача — multivariate (многомерный) forecasting с horizon (горизонтом) 144 шага: один вход даёт сразу 144 прогнозных значения, а не одно. Вход — окно lookback (окно истории) = 144 шага по пяти каналам, выход — 144 значения целевой. Ряд имеет шаг 10 минут, поэтому 144 шага — это ровно 24 часа.

Сравнение идёт с тремя baseline: persistence (naive forecast) — повторить последнее известное значение; constant — повторить среднее по train; linear — Ridge-регрессия на всех лагах всех каналов. Все модели оцениваются на одном и том же test.

2. Данные

Источник — 10-минутные статистики каналов GOCE (5 parquet-файлов). После объединения по timestamp получилось 239,616 строк. Пропуски в value_mean составляют 3,515 % и совпадают с value_count = 0: нулевой счётчик означает, что измерения не было, а не что значение равно нулю.

После удаления строк с NaN осталось 231,194 строк. Длинных NaN-серий (дольше 6 шагов) — 3, самая длинная — 7,270 шагов ≈ 50,5 суток. Ряд остаётся регулярным по индексу, но физически разорван: окна, пересекающие разрыв, выбрасываются, иначе модель училась бы на склейке разных месяцев.

Каналы: PHT10080 (заряд), PHT10100 (разряд), PHT10180 (напряжение, целевая), PHT10260 и PHT10300 (температуры TMP_1 и TMP_2).

3. Методология

Split — хронологический 70/15/15. Границы: train 0– 161,836, val 161,836–196,515, test 196,515–231,194 (по строкам ряда). Окна не пересекают границы: train — 13,384, val — 2,842, test — 2,866. Шаг между окнами — 12 шагов (2 часа).

Нормализация — только по train. StandardScaler обучается на строках train и применяется к val/test; целевая масштабируется тем же scaler и возвращается в вольты перед подсчётом MAE. Иначе среднее и std теста попали бы в обучение.

Модель. LSTM(64) → Dense(32, ReLU) → Dense(144), dropout 0.1, Adam с lr 1e-3, batch 128, MSE-loss, EarlyStopping по val_loss с patience 8. Одна модель выдаёт весь горизонт сразу (direct multi-step), а не рекурсивно.

Метрики. MAE, RMSE, R² и skill score = 1 − MAEмодели / MAEpersistence. Skill score положителен, только если модель лучше naive-прогноза.

Проверки leakage. Нормализация — только train; окна не пересекают границы сплитов; value_last, value_sum, value_count, value_min, value_max как признаки не используются; история окна заканчивается до первого шага горизонта. Все проверки пройдены: true.

3.1. Архитектура

Используются две конфигурации LSTM с direct multi-step прогнозом. Базовая A: LSTM(64) → Dense(32, ReLU) → Dense(144), dropout 0.1, 24 752 параметра. Расширенная D: LSTM(128) → Dense(64, ReLU) → Dense(144), dropout 0.2, 86 224 параметра. На вход подаётся окно 144×5 (24 часа истории по пяти каналам), на выходе сразу 144 шага горизонта. Loss — MSE, оптимизатор Adam с learning rate 1e-3, batch 128, early stopping по val_loss с patience 8, до 30 эпох, seed 42.

LSTM выбрана потому, что ряд сильно сезонный: суточная корреляция (лаг 144) выше минутной, и модели нужно удерживать контекст длиной в сутки. Direct-схема выдаёт весь горизонт за один проход и не накапливает ошибку рекурсивного шага. Две конфигурации проверяют, даёт ли рост ёмкости заметный выигрыш: D лучше A по MAE на test (0,1906 против 0,1985 В), но разница невелика, поэтому обе остаются в сравнении.

5. Анализ ошибок

MAE по шагам горизонта у A_базовая: первый шаг — 0,1105 В, середина — 0,1894 В, последний — 0,3419 В. Максимум — на шаге 140 (0,3457 В). Ошибка растёт не монотонно: модель уверенно держит суточный цикл, но проваливается на резких переходах заряда и разряда. Средний MAE по всем 144 шагам для A_базовая — 0,1985 В, то есть первый и последний шаги — это разные способы агрегации одной и той же модели, а не разные модели.

Почему LSTM лучше persistence. Persistence на 24 часа вперёд повторяет последнее значение; за сутки напряжение успевает пройти цикл заряда и разряда, поэтому такая копия систематически ошибается. LSTM выучивает суточный ход и переносит его на горизонт: MAE падает с 0,6765 В (persistence) до 0,1906 В (D_большая).

Разрыв в 50,5 суток — главная причина, по которой часть окон выброшена: склейка «до» и «после» разрыва дала бы модели фиктивную непрерывность. Сколько окон потеряно из-за разрывов и границ, видно в split_info.json: 103 окон отброшено по разрывам, 48 — по границам сплитов.

7. Выводы

  1. Лучший результат — D_большая: MAE 0,1906 В, RMSE 0,3294 В, R² 0,777, skill score 0,718.
  2. MAE лучшей модели (D_большая) — 0,1906 В, MAE linear baseline — 0,2572 В. Модель лучше на 0,0666 В (25,9 % снижения MAE относительно linear).
  3. Многомерный вход лучше одномерного на -0,0230 В MAE (-10,4 %).
  4. Все обученные варианты лучше persistence: skill score положителен у каждой строки таблицы. Это ожидаемо — naive-прогноз на 24 часа не удерживает суточный цикл.
  5. Ряд содержит разрыв 50,5 суток и 3,515 % пропусков; окна через разрыв выброшены, поэтому модель не видит склеек.

8. Ограничения

  • Один seed. Все прогоны выполнены с seed=42; разброс между запусками не измерен, поэтому различия в пределах 0,005 В MAE нельзя считать значимыми.
  • Разрыв 50,5 суток и 3,515 % пропусков сокращают непрерывную историю; поведение на границах разрыва не проверялось.
  • Перекрытие окон. Шаг 12 при lookback 144 и horizon 144 означает сильное перекрытие соседних окон; эффективная выборка меньше 13,384.
  • R² на длинном горизонте считается по всем 144 точкам сразу; отрицательный R² у persistence и constant отражает не «плохую модель», а узкую дисперсию целевой на горизонте.
  • Только 5 каналов из 327 в metadata.csv; остальные не использовались.
  • CPU-only: TensorFlow не видит GPU, поэтому обучение ограничено 30 эпохами и небольшими сетями.
  • Корреляция 0,972. Разрядный ток (PHT10100_mean) сильно коррелирует с напряжением — это физическая связь, а не утечка. Permutation importance на A показала, что перестановка тока повышает MAE заметно меньше, чем перестановка самой целевой, то есть шортката нет.
  • Direct multi-step. Модель предсказывает все 144 шага сразу; рекурсивный вариант (шаг за шагом) не проверялся.
  • Permutation importance только для A. Для остальных конфигураций важность признаков не считалась.

10. Приложение

10.1. Схема пайплайна

  1. Чтение 5 parquet и inner join по timestamp.
  2. Удаление строк с NaN; фиксация длинных NaN-серий как разрывов.
  3. Хронологический split 70/15/15 по строкам.
  4. StandardScaler fit на train, transform на val/test.
  5. Окна (144, 5) → (144) с шагом 12; окна через разрыв и границы сплитов выброшены.
  6. LSTM/GRU, EarlyStopping, оценка на val; test — один раз после обучения.
  7. Baseline и абляции на том же test; сборка JSON и графиков.

10.2. Выходные файлы

  • data/interim/data_summary.json — профиль ряда, корреляции, автокорреляция.
  • data/processed/split_info.json — границы и число окон по сплитам.
  • reports/summary_baselines.json — persistence, constant, linear.
  • reports/experiments/*.json — метрики каждого прогона и история обучения.
  • reports/metrics_experiments.json, reports/ablation_results.json.
  • reports/leakage_check.json — проверки утечек.
  • reports/figures/01–04 — ряд, прогноз, MAE по шагам, сравнение.

10.3. Как воспроизвести

python scripts/prepare_data.py
python scripts/run_baselines.py
python scripts/permutation_importance.py
python scripts/check_leakage.py
python scripts/run_experiment.py --name A --save-model
python scripts/run_experiment.py --name B
python scripts/summarize.py
python scripts/make_figures.py
python scripts/build_report.py
pytest -q

10.4. Направления дальнейшей работы

  • Разрыв 50,5 суток — естественный пропуск телеметрии; в дальнейшем можно проверить, не является ли он ошибкой выгрузки.
  • Direct multi-step выбран вместо recursive; в дальнейшем можно сравнить оба подхода на одном горизонте.
  • Использованы 5 каналов из 327 (батарейная подсистема); в дальнейшем набор можно расширить.
  • Permutation importance проведена для конфигурации A; для остальных конфигураций её ещё предстоит повторить.
