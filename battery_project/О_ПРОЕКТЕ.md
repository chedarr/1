# О проекте — Лабораторная №1: регрессия нейросетями (NASA Battery)

Короткая карта проекта: что считается, что лежит в папках, как запустить и что важно
помнить. Подробности — в `README.md`, числа — в `data/processed/*.json`.

## Теоретически: что и зачем

**Задача.** Три независимые задачи регрессии на данных старения литий-ионных
аккумуляторов NASA PCoE (34 файла `.mat`, в каждом — серия зарядно-разрядных циклов).

| Задача | Цель | Батарей |
|---|---|---:|
| A: RUL | `RUL_frac` = остаточные циклы / полная длина серии, доли | 8 |
| B: напряжение | напряжение следующего цикла, В | 34 |
| C: ёмкость | ёмкость следующего цикла, А·ч | 33 |

`RUL` (remaining useful life) — остаточный ресурс; нормировка на длину серии нужна,
чтобы батареи разной длины были сопоставимы.

**Модель.** Одна архитектура на все три задачи: `Dense(64) → Dropout(0.2) → Dense(32) →
Dense(1)`, loss = MSE, `EarlyStopping`. Признаки — статистики цикла (температуры,
напряжения, ток, длительности, лаги и разности), 14 / 13 / 10 штук по задачам.

**Как оцениваем.** Сплит строго по батареям (`GroupShuffleSplit`): циклы одной батареи
не попадают одновременно в train и test, иначе модель запоминает конкретный экземпляр.
Нормализация обучается только на train. Сравнение — с тремя baseline на том же сплите:
константа (среднее по train), линейная регрессия, Random Forest (100 деревьев).

**Главный вывод.** MLP обыгрывает все baseline только в задаче A (R² 0.8023). В B и C
лучше линейная регрессия (R² 0.8684 и 0.8424): эти задачи почти линейны, а данных мало.
Проигрыш написан в отчёте явно, а не спрятан.

### Метрики на тесте

| Задача | MAE | RMSE | R² |
|---|---:|---:|---:|
| A: RUL_frac | 0.108867 | 0.129426 | 0.802316 |
| B: напряжение | 0.156747 | 0.259169 | 0.048058 |
| C: ёмкость | 0.138128 | 0.267759 | 0.757734 |

Для A дополнительно `mae_cycles` = 12.96 цикла при средней длине тестовой серии 119 циклов.

## Как запустить

```powershell
python scripts/run_all.py        # парсинг → признаки → обучение → отчёты
python scripts/run_baselines.py  # baseline-модели и сравнение
python -m pytest tests -q        # тесты
python scripts/check_leakage.py  # проверка утечек
```

## Что важно знать

- Данных мало: RUL — 8 батарей, тест — 2 батареи. Метрики сильно зависят от того,
  какие батареи попали в тест; разброс не измерялся через CV.
- Температурный сдвиг: train-батареи RUL сняты при 4 °C, валидационные — при 24 °C,
  тест смешанный. Вклад температурных признаков отражает условия съёмки, а не физику.
- `data/` (~198 МБ) и `_trash/` в git не попадают — см. `.gitignore`.
- Число рисунков в `README.md` (18) устарело: в `Итоговый отчёт/figures/` лежит 33 PNG.
  Источник истины — JSON в `data/processed/`, а не текст README.
