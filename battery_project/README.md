# Лабораторная работа №1 — Регрессия нейросетями (NASA Battery)

Три задачи регрессии MLP на NASA PCoE Battery Dataset (34 .mat файла):

- **A: RUL** — нормированная доля остаточного ресурса `RUL_frac = RUL_cycles/total_cycles`,
  8 батарей с полной кривой деградации (RUL_cycles остаётся для интерпретации).
- **B: напряжение следующего цикла** — все 34 батареи.
- **C: ёмкость следующего цикла** — все 34 батареи.

Одна архитектура `Dense(64→32)→Dropout(0.2)→Dense(1)`, Loss=MSE,
EarlyStopping, сплит строго по батареям (GroupShuffleSplit, test 25%).

## Запуск

```
python scripts/run_all.py      # весь пайплайн: парсинг → признаки → обучение → отчёт
python -m pytest tests -q      # тесты
```

## Сравнение с базовыми предсказателями

Три baseline на том же сплите по батареям и с тем же препроцессингом: константа
(среднее значение цели по train), линейная регрессия, Random Forest (100 деревьев).
R² на тесте:

| Задача | MLP | константа | линейная регрессия | Random Forest |
|---|---:|---:|---:|---:|
| A: RUL_frac | **0.8023** | 0.0000 | -2127.86 | -0.7499 |
| B: Напряжение | 0.0481 | -0.0478 | **0.8684** | 0.5711 |
| C: Ёмкость | 0.7577 | -0.0067 | **0.8424** | 0.7025 |

MLP превосходит все baseline **только** по RUL_frac. По напряжению и ёмкости лучше
линейная регрессия: обе задачи в этой постановке почти линейны, а MLP на 8–34 батареях
переобучается (3073 / 3009 / 2817 параметров против 15 / 14 / 11). На RUL_frac
тестовая батарея B0006 (167 циклов) длиннее любой обучающей серии (максимум 71 цикл),
поэтому линейная регрессия уходит в нефизичную область (R² = -2127.86), а MLP
единственная модель, удерживающая цель в диапазоне [0, 1].

Источник чисел — `data/processed/summary_baselines.json`, график —
`reports/figures/baseline_comparison.png`.

## Проверка утечек

Проверить самостоятельно: `python scripts/check_leakage.py`.

1. **Лаги** — `voltage_mean_lag1/lag2`, `capacity_lag1/lag2/lag3` строятся
   `shift(+1/+2/+3)` (прошлые циклы); `shift(-1)` используется только для целей
   следующего цикла.
2. **Нормализация** — `SimpleImputer`/`StandardScaler` обучаются только на train.
3. **Сплит** — `GroupShuffleSplit` по `battery_id`; пересечений train/val/test нет.
4. **Вход модели** — колонки, нужные только для построения цели и разбиения
   (номер цикла, длина серии, дата, идентификатор батареи, время цикла), в
   `feature_cols` не подаются; проверено и по сохранённым `metrics_*.json`.
5. **Feature importance** — permutation importance считается на тестовых батареях
   при обучении на train (`scoring="r2"`, `n_repeats=5`): топ-3 — `temp_max` (9.17),
   `temp_mean` (5.91), `temp_min` (1.21). В задаче RUL все батареи train сняты при
   4 °C, обе валидационные — при 24 °C, тест — смешанный, поэтому вклад температурных
   признаков отражает в первую очередь различия условий съёмки.

## Ограничения

- Для RUL только 8 батарей, тест — 2 батареи: метрики сильно зависят от того, какие
  батареи попали в тест.
- Длина серии известна в датасете заранее, поэтому `mae_cycles` — приближённая
  интерпретация нормированной метрики, а не независимая метрика.
- B0052 (4 разрядных цикла) выпадает из задачи C после честного `dropna` — 33 батареи.
- Аномальные батареи (например, B0050 в задаче напряжения) остаются в датасетах
  и ухудшают агрегированные метрики.
- Модель работает со статистиками цикла, а не с полными кривыми разряда: импеданс
  и температурные зависимости не моделируются.
- Перенос прогноза на батареи с другими условиями съёмки не проверялся.
- Гиперпараметры (слои, `lr`, `batch`) подбирались вручную, без поиска по сетке.
