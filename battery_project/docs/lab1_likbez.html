1. Что это за работа

Предмет — регрессия на табличных данных нейросетью. Задача: по измерениям литий-ионной батареи за несколько циклов предсказать числовую величину — остаточный ресурс, напряжение или ёмкость следующего цикла.

Почему регрессия, а не классификация. Классификация отвечает на вопрос «к какому из конечного числа классов относится объект» (да/нет, тип дефекта, исправна/неисправна). Регрессия отвечает на вопрос «какое число здесь» — с непрерывной шкалой и без заранее заданного конечного набора вариантов.

Здесь цели заранее непрерывны и в любой момент принимают новое значение: ресурс падает от 1.0 к 0.0 постепенно, а не прыгает между состояниями. Классов «ресурс = 0.5» или «ёмкость = 1.4 А·ч» в природе не существует — их пришлось бы искусственно квантовать, и информация потерялась бы уже на самом шаге постановки задачи. Поэтому классификатор здесь был бы не точной, а огрублённой заменой регрессора.

Классификация в этой же работе применима к другой постановке — «доживёт ли батарея до EOL / пересечёт ли порог отсечки» — но такая формулировка требует разметки на два класса, которой в датасете нет.

Три задачи

Задача Что предсказываем Масштаб цели Смысловая метрика
RUL_frac доля остаточного ресурса: сколько ещё можно отработать 0.0 … 1.0 (безразмерно) MAE_cycles — средняя ошибка в пересчёте на циклы, понятно инженеру
voltage среднее напряжение следующего разрядного цикла, В ≈ 3.9 … 4.2 В MAE в вольтах — абсолютная ошибка напряжения
capacity ёмкость следующего разрядного цикла, А·ч ≈ 0.7 … 1.6 А·ч MAE в А·ч — насколько промахнулись по ёмкости

Цели строятся так:

  • RUL_frac = RUL_cycles / total_cycles, где RUL_cycles = total_cycles − номер цикла, а total_cycles — число разрядных циклов батареи.
  • voltage_mean_next = voltage_mean.shift(-1)
  • capacity_next = capacity.shift(-1)

Про RUL_cycles в абсолютных единицах: без нормировки ошибка зависит от длины серии — у длинных батарей абсолютный RUL больше, и модель вынуждена экстраполировать на серии длиннее обучающих (в train максимум 71 цикл, в тесте B0006 — 167 циклов). Нормировка на длину жизни сняла эту зависимость: MAE = 0.108867 в долях, то есть около 13 циклов.

2. Откуда данные

Источник: NASA PCoE Battery Aging Dataset (Battery Data Set), 34 литий-ионные батареи B0005–B0056. Каждую гоняли циклами заряд/разряд до износа, внутри камеры с фиксированной ambient-температурой.

Формат — .mat (MATLAB v5). Верхний уровень: массив структур, внутри — поле cycle, а каждый элемент cycle содержит:

Поле Содержимое
cycle.type 'charge' / 'discharge' / 'impedance'
cycle.ambient_temperature температура камеры (°C)
cycle.time [год, месяц, день, час, минута, секунда]
cycle.data массивы измерений

В cycle.data для типа discharge лежат Voltage_measured, Current_measured, Temperature_measured, Current_load, Voltage_load, Time, Capacity; для charge — без Capacity; для impedance — Re и Rct.

Единицы измерения. Напряжение — вольты, ток — амперы, температура — °C, ёмкость — А·ч (Ah), время внутри цикла — секунды, импеданс Re/Rct — омы. Таймстемп — локальное время без зоны, из массива [Y, Mo, D, h, m, s].

Что реально используется — только циклы разряда. Из трёх типов циклов в таблицу измерений попадает только discharge; остальные два присоединяются как события по времени (merge_asof, направление backward):

  • duration_charge — длительность последнего перед разрядом цикла заряда;
  • re, rct — значения последнего перед разрядом цикла импеданса.

Причина в физике: ёмкость, напряжение и температура измеряются на разряде, и только там цикл считается «полным». Импедансные циклы в датасете идут разреженно, поэтому присоединение по дате — единственный способ не получить дырки.

Сколько батарей в каждой задаче (сверено с metrics_*.json):

Задача Батарей Строк train / val / test
RUL_frac 8 272 / 300 / 240
voltage 34 1280 / 686 / 696
capacity 33 1377 / 565 / 686

Разница в 34 и 33 — одна батарея (B0052) даёт всего 4 разрядных цикла, чего не хватает для скользящих лагов; она не попадает в задачу ёмкости. В RUL попадают только 8 батарей: у остальных кривая деградации не доходит до порога отсечки (12 батарей числятся в artifacts/no_eol_batteries.json с причиной no_crossing_censored), то есть полного вектора RUL_frac для них не существует.

3. Что было сделано по шагам

Шаг 1. Парсинг .mat → parquet

Все 34 файла прочитаны через scipy.io.loadmat(struct_as_record=False, squeeze_me=True): взят верхний ключ (первый, не начинающийся с __), разобрана структура cycle, оставлены только discharge-циклы, циклы пронумерованы по порядку с нуля.

Результат: data/processed/raw_cycles.parquet — 2769 строк × 23 колонки.

Шаг 2. Чистка

Физически невозможные значения отбрасываются по трём правилам:

  • capacity вне диапазона [0, 2.6];
  • любая колонка voltage_* < 0;
  • re или rct вне [0, 1] (омы).

Плюс два отдельных шага: флаг is_low_capacity для строк с capacity < 0.5 (низкие ёмкости помечаются, но не удаляются — они физически валидны), и фильтр выбросов импеданса по MAD: |x − median| > 5·MAD → NaN, далее ffill внутри батареи.

Результат: clean_cycles.parquet — 2764 строки (снято 5 строк), затем battery_features.parquet — 2764 строки × 39 колонок.

Шаг 3. Признаки

Из 23 сырых колонок достроены производные до 39:

  • лаги из прошлых циклов: voltage_mean_lag1, voltage_mean_lag2, capacity_lag1, capacity_lag2, capacity_lag3 — сдвиг назад (shift(+k)), то есть физически наблюдаемое прошлое;
  • динамика: voltage_diff, capacity_diff, capacity_slope, discharge_rate;
  • нормировка ёмкости: capacity_ratio = capacity / cap0, где cap0 — ёмкость первого цикла батареи;
  • колонки пайплайна для построения целей: total_cycles, voltage_mean_next, capacity_next — из них voltage_mean_next и capacity_next становятся целями, а total_cycles нужен для нормировки RUL_frac. В сеть они не подаются.

Ключевой принцип: shift(+k) — только для признаков (прошлое наблюдаемо), shift(−1) — только для целей (следующий цикл ещё не измерен). Смешивать эти два направления нельзя: цель, собранная из shift(+1), протекала бы в признак.

Шаг 4. Отбор признаков

В каждую задачу взят свой набор признаков — по 14 / 13 / 10, по физической релевантности цели:

  • RUL_frac (14): voltage_mean, voltage_min, voltage_max, voltage_std, current_mean, temp_mean, temp_min, temp_max, temp_range, time_total, capacity, capacity_ratio, voltage_range, discharge_rate.
  • voltage (13): 7 из тех же + capacity_lag1, voltage_mean_lag1, voltage_mean_lag2, voltage_diff. Лаги напряжения здесь ключевые: цель — shift(−1), а предыдущее значение известно.
  • capacity (10): capacity, capacity_ratio, voltage_mean, current_mean, temp_mean, capacity_lag1, capacity_lag2, capacity_lag3, capacity_diff, capacity_slope. Дальние лаги ёмкости — прямой код тренда деградации.

Шаг 6. Разделение данных — по батареям, а не по строкам

GroupShuffleSplit с test_size = 0.25, random_state = 42, группирующая колонка — battery_id. Второй шаг делит остаток на train/val.

Почему нельзя смешивать циклы одной батареи между train и test. Это утечка, и на этих данных она была бы особенно грубой, потому что в признаках есть лаги. Соседние строки одной батареи почти идентичны: capacity_lag1 в строке N и capacity в строке N−1 — это одно и то же число. При случайном разбиении по строкам половина теста — это копия train, модель не выучивает связь «признаки → цель», а запоминает конкретные батареи, и R² выходит завышенным на порядок.

Конкретный сплит RUL (пересечений нет, все 8 батарей использованы):

Часть Батареи ambient
train B0045, B0046, B0048, B0053 все 4 °C
val B0005, B0018 обе 24 °C
test B0006 (24 °C), B0047 (4 °C) смешанная

Сплит честен по утечке, но у него есть важная особенность условий: все батареи train сняты при 4 °C, обе батареи val — при 24 °C, а test смешанный. То есть по температуре в test батарея опознаётся безошибочно, и вклад temp_* в permutation importance отражает в первую очередь различия условий съёмки (подробно в разделе 6).

Для voltage: 18 train / 7 val / 9 test (34 батареи). Для capacity: 18 / 6 / 9 (33 батареи).

Шаг 7. Предобработка

SimpleImputer(strategy="median") + StandardScaler, и оба обучены только на train. Это не формальность: если скалер обучается на всём датасете, тестовые строки участвуют в вычислении среднего и отклонения, то есть их значения «просачиваются» в параметры препроцессинга. На коротких лагах с NaN в начале серии медиана train заметно отличается от медианы теста.

Шаг 8. Метрики

Метрика Формула Что показывает Чего не показывает
MAE среднее |y − ŷ| средняя ошибка в единицах цели не штрафует редкие крупные промахи
RMSE корень из среднего квадрата ошибки штрафует выбросы сильнее MAE зависит от масштаба цели
R² 1 − SS_res/SS_tot доля дисперсии цели, объяснённая моделью может быть отрицательным — это хуже константы
MAE_cycles MAE_frac × среднее total_cycles теста ошибка в циклах, инженерная величина зависит от того, какие батареи попали в test

Что «лучше». Меньше MAE и RMSE, больше R². Но R² требует базы сравнения: у константного предсказателя R² = 0.0, а значение ниже нуля означает, что модель хуже, чем просто выдать среднее. И R² нельзя читать, не зная MAE_cycles: R² = 0.80 на цели 0…1 и R² = 0.80 на цели 0…1000 — это разные по физике вещи.

4. Модели и базовые предсказатели

Один MLP-шаблон на все три задачи. Чтобы честно ответить на вопрос «даёт ли нейросеть что-то сверх простых моделей», считаются три базовых предсказателя на том же сплите по батареям и с тем же препроцессингом.

Предсказатель Что это Параметров
MLP Dense(64) → Dropout(0.2) → Dense(32) → Dense(1) 3073 / 3009 / 2817
константа среднее значение цели по train-строкам, выданное на все строки теста 1
линейная регрессия LinearRegression на тех же признаках после imputer + scaler 15 / 14 / 11
Random Forest 100 деревьев, random_state = 42, median-imputer (scaler не нужен) —

Зачем вообще baseline. Метрика сама по себе ничего не значит: R² = 0.8 — это хорошо или плохо? Ответить можно только рядом с простым предсказателем. У константы R² = 0 по построению, то есть это уровень «выдать одно и то же число всем». Модель ниже нуля хуже константы, и никакая архитектура этого не оправдывает. Поэтому baseline — не формальность, а рамка честности.

R² на тесте, лучший предсказатель по задаче выделен жирным:

Задача MLP константа линейная регрессия Random Forest лучший
A: RUL_frac 0.8023 0.0000 -2127.86 -0.7499 MLP
B: Напряжение 0.0481 -0.0478 0.8684 0.5711 линейная регрессия
C: Ёмкость 0.7577 -0.0067 0.8424 0.7025 линейная регрессия

Полные MAE/RMSE — в отчёте (раздел 5.4) и в data/processed/summary_baselines.json, график — reports/figures/baseline_comparison.png.

RUL_frac — MLP побеждает

Константа даёт ровно 0.0000, Random Forest уходит в минус (-0.7499): на 8 батареях деревья переобучаются и оказываются хуже константы. Линейная регрессия ломается об экстраполяцию: R² = -2127.86 при MAE = 11.261 доли, тогда как цели лежат в [0, 1]. Причина конкретная: тестовая батарея B0006 (167 циклов) длиннее любой серии в обучающей выборке (максимум 71 цикл), и линейный прогноз уходит в нефизичную область. MLP — единственная из четырёх моделей, удерживающая RUL_frac в осмысленном диапазоне.

Напряжение — MLP проигрывает

R²(MLP) = 0.0481 (MAE = 0.1567 В) против R²(LR) = 0.8684 (MAE = 0.0388 В) и R²(RF) = 0.5711. Тот же сплит, тот же препроцессинг — и простая линейная модель объясняет 87 % дисперсии напряжения следующего цикла там, где MLP даёт около нуля. Это важная оговорка к разделу 5: низкий R² здесь — не «задача нерешаема», а свойство именно этой архитектуры на этом наборе.

Ёмкость — снова линейная регрессия, но MLP обгоняет деревья

R²(MLP) = 0.7577 (MAE = 0.1381 А·ч) против R²(LR) = 0.8424 (MAE = 0.0975 А·ч) и R²(RF) = 0.7025. Цель capacity_next сильно коррелирует с текущей ёмкостью и её лагами, и линейный предиктор выжимает из этих признаков больше, чем MLP.

Итог. MLP превосходит все три baseline только по RUL_frac. На двух задачах из трёх линейная регрессия лучше, и это не дефект MLP: у линейной модели 15 / 14 / 11 параметров, у сети — 3073 / 3009 / 2817, а батарей всего 8–34. Сложность модели должна соответствовать сложности задачи и объёму данных.

Ошибка в 12.955 цикла при средней полной жизни 119 циклов — около 11 %. Разрыв train/val ≈ 0.019: умеренный обобщающий разрыв, а не драматичная деградация, ранняя остановка и Dropout свою работу делают.

Честные выводы

  1. RUL_frac работает внутри известного распределения. R² = 0.802, ошибка 12.955 цикла — это честная интерполяция по батареям, которых модель не видела.
  2. Ёмкость работает внутри известного распределения. R² = 0.758. На тесте есть выброс — B0042 с MAE 0.373 против 0.024–0.153 у остальных восьми.
  3. Напряжение почти не объясняется. R² = 0.048 у MLP. Основной вклад в ошибку даёт B0050 (MAE ≈ 1.10 В против 0.065–0.254 у остальных), но выброс не оправдание: линейная регрессия на том же сплите даёт 0.868 (раздел 4).
  4. MLP выигрывает не на всех задачах — только на RUL_frac. Это главный результат сравнения, а не формальность.
  5. Важность признаков указывает на условия съёмки. Permutation importance (обучение на train, перестановка на test): temp_max 9.17, temp_mean 5.91, temp_min 1.21, дальше current_mean 0.48 и capacity_ratio 0.46. В задаче RUL батареи train сняты при 4 °C, валидационные при 24 °C, тест смешанный, поэтому температурные признаки в первую очередь различают батареи и условия измерения, а не только описывают деградацию.

6. Спорные моменты

(а) Зачем MLP, если на двух задачах лучше линейная регрессия?

Факт. RUL_frac: MLP 0.802 против 0.000 у константы и -0.750 у Random Forest, линейная регрессия ломается на экстраполяции (-2127.86). Напряжение: 0.048 у MLP против 0.868 у линейной. Ёмкость: 0.758 у MLP против 0.842 у линейной.

Как это читать. Задачи напряжения и ёмкости в этой постановке почти линейны: следующее значение сильно связано с текущим и его лагами. Линейная модель с 11–15 параметрами на 33–34 батареях такое предсказание выучивает, а сеть с 2817–3073 параметрами — переобучается. Задача RUL_frac нелинейна (остаточный ресурс зависит от формы кривой деградации и от того, где находится цикл внутри серии) и требует экстраполяции за пределы обучающих серий — здесь MLP оправдан.

Практический вывод. MLP не панацея, а инструмент под конкретную задачу: для RUL_frac — да, для напряжения и ёмкости — линейная регрессия. Это не повод убрать нейросеть из работы, а повод писать о ней честно.

(б) voltage: R² = 0.048

Что это значит формально. MLP объясняет 4.8 % дисперсии voltage_mean_next. MAE = 0.157 В при разбросе цели около 0.06–0.25 В на «нормальных» батареях: модель частично работает, но дисперсию не объясняет.

Почему так. Задача next-cycle по напряжению на разряде 2C жёсткая: форма кривой задаётся режимом, а не состоянием. Межцикловой скачок среднего напряжения слабо связан с ёмкостью, током и температурой в наборе признаков. Плюс выброс B0050 (MAE ≈ 1.10 В) тянет и MAE, и RMSE вверх.

Честный вывод, а не «дотянуть». Метрику подгонкой не поднимать: убрать B0050 из теста — значит выбросить неудобную батарею и сообщить об этом как об улучшении. И главное — низкий R² здесь не приговор задаче: линейная регрессия на тех же данных даёт 0.868.

(в) Как читать permutation importance, если условия съёмки различаются

Permutation importance честно посчитана: imputer, scaler и MLP обучены на train-батареях, перестановка признаков и подсчёт scoring="r2", n_repeats = 5 — на тестовых строках. Но в задаче RUL train — это батареи при 4 °C, val — при 24 °C, а тест смешанный. Признак, который различает группы, всегда даст большой вклад на смешанной выборке, поэтому temp_max 9.17 и temp_mean 5.91 отражают в первую очередь различия условий съёмки, а не только физику деградации. Это не повод выбрасывать признаки: саморазогрев при износе реален, внутрибатарейный тренд temp_mean растёт с деградацией. Это повод честно подписать, что именно измеряет величина.

(г) MAE_cycles — метрика или пересчёт?

MAE_cycles = MAE_frac × средняя длина серии теста = 12.955 цикла. Величина понятная инженеру, но она опирается на длину серии, которая в датасете известна заранее, а в эксплуатации — нет. Поэтому 12.955 цикла стоит читать как приближённую интерпретацию нормированной метрики (около 11 % от 119 циклов), а не как независимую метрику.

7. Что спросить у преподавателя

  1. Про честность вывода. MLP превосходит все baseline только по RUL_frac, а по напряжению и ёмкости линейная регрессия лучше (0.868 и 0.842 против 0.048 и 0.758). Это ожидаемое поведение для 8–34 батарей, или работу стоит продолжать в сторону архитектуры и регуляризации?

  2. Про объём данных. Для RUL отдано 8 батарей, и тест — это 2 батареи (25 %). Оправдано ли выделение 8 батарей на одну задачу и 33–34 на две другие, или стоит сузить постановку до одной задачи и сделать её глубже?

  3. Про voltage при R² ≈ 0. Что означает R² = 0.048 для задачи «среднее напряжение следующего цикла» с низкой межцикловой дисперсией? Корректнее ли в этой формулировке вообще опираться на R², и достаточно ли MAE в вольтах? Есть ли постановка этой задачи, где R² был бы информативен?

  4. Про условия съёмки. В задаче RUL все батареи train при 4 °C, обе валидационные при 24 °C, тест смешанный. Считать ли корректной permutation importance при таком сплите, и стоит ли приводить temp_* к виду «отклонение от ambient», чтобы они описывали саморазогрев, а не условия камеры?

  5. Про состав baseline. Достаточно ли трёх базовых предсказателей (константа, линейная регрессия, Random Forest), или стоит добавить kNN, градиентный бустинг и ансамбли по нескольким seed?

  6. Про улучшения, в порядке ожидаемого эффекта. Что пробовать в первую очередь: подбор гиперпараметров (слои, lr, batch), ансамбли по seed, калибровку предсказаний в [0, 1], увеличение числа батарей или смену постановки цели для voltage?

8. Термины

Регрессия — предсказание непрерывной числовой величины. Классификация — предсказание дискретной категории из конечного набора. MLP (многослойный персептрон) — нейросеть из последовательности полносвязных слоёв. Dense — полносвязный слой: каждый нейрон получает линейную комбинацию всех входов предыдущего слоя. ReLU — функция активации max(0, x); на нём обучается MLP. Dropout — регуляризация: на каждом шаге случайная доля нейронов обнуляется, сеть не может опираться на них всех. Backpropagation — обратное распространение ошибки: вычисление градиентов весов от выхода к входу. MSE (mean squared error) — средний квадрат ошибки, функция потерь; сильно штрафует крупные промахи. MAE (mean absolute error) — средняя абсолютная ошибка, метрика в единицах цели. RMSE (root mean square error) — корень из MSE, метрика с квадратичным штрафом за выбросы. R² (коэффициент детерминации) — доля дисперсии цели, объяснённая моделью; 0.0 у константы, отрицательное значение — хуже константы. RUL (remaining useful life) — остаточный полезный ресурс: сколько циклов батарея ещё проработает. RUL_frac — RUL в долях от полной жизни батареи, величина 0…1. MAE_cycles — MAE для RUL, пересчитанная в циклы: MAE_frac × средняя длина серии теста. Лаг (shift) — значение того же признака, взятое на k циклов раньше; shift(+k) — прошлое, shift(−1) — следующий цикл. Нормировка — приведение величины к безразмерному виду, чтобы сравнивать разные батареи; здесь RUL_frac и capacity_ratio. StandardScaler — приведение признака к нулевому среднему и единичному отклонению; обучается только на train. Imputation — заполнение пропусков; здесь медианой, обученной на train. Split — разделение данных на train / validation / test. GroupShuffleSplit — разбиение, где вся батарея целиком уходит в одну часть (train/validation/test), а её циклы не оказываются в разных частях. Утечка (leakage) — ситуация, когда информация из test попала в обучение напрямую или через соседние строки той же батареи. Seed — фиксированное число для воспроизводимости: с ним обучение повторяется до последнего шага. Парсинг — разбор файлов формата .mat в таблицу. Пайплайн — фиксированная последовательность шагов от сырых данных до метрик. Feature importance — оценка вклада признака в качество модели. Permutation importance — важность как падение R² при перестановке значений признака в тесте; устойчивее весов сети. Baseline — простой предсказатель, с которым сравнивают модель: здесь константа (среднее train), линейная регрессия и Random Forest; у константы R² = 0.0. Константный предсказатель — модель, выдающая одно и то же число; на тесте даёт R² = 0.0 по построению. Линейная регрессия — модель целиком из линейной комбинации признаков; здесь 15 / 14 / 11 параметров вместе со сдвигом. Random Forest — ансамбль решающих деревьев; на малой выборке склонен переобучаться. Экстраполяция — прогноз за пределы того, что модель видела; в задаче RUL это серии длиннее любой обучающей. Early stopping — остановка обучения, когда валидационная метрика перестала улучшаться; здесь patience = 10.

9. Как объяснить процесс

Коротко, своими словами, по шагам работы.

Данные: NASA Battery, 34 батареи в .mat. Внутри каждого файла циклы трёх типов: заряд, разряд, импеданс. Взяты циклы разряда, к ним приложены длительность последнего заряда и значения последнего импеданса по времени. Получено 2769 строк, после чистки 2764 строки и 39 колонок-признаков.

Признаки: лаги из прошлых циклов, разности, скорость разряда, нормированная ёмкость. Правило: shift(+k) — только в признаки, shift(−1) — только в цели. Иначе цель протекла бы во вход.

Три задачи регрессии: доля остаточного ресурса, среднее напряжение следующего цикла, ёмкость следующего цикла. RUL — на 8 батареях с полной кривой деградации, напряжение — на 34, ёмкость — на 33.

Модель: MLP Dense(64) → Dropout(0.2) → Dense(32) → Dense(1), MSE, Adam, EarlyStopping. Разбиение — по батареям, GroupShuffleSplit: в признаках есть лаги, и при разбиении по строкам соседние циклы одной батареи оказались бы одновременно в train и test, то есть утечка. Скалер и импутер обучены только на train.

Сравнение с базовыми предсказателями на том же сплите: константа, линейная регрессия, Random Forest. RUL_frac — MLP 0.802 против 0.000 у константы; напряжение — 0.048 у MLP против 0.868 у линейной регрессии; ёмкость — 0.758 у MLP против 0.842 у линейной. Причина разницы — не «нейросеть хуже», а разная сложность задач: напряжение и ёмкость почти линейны, а RUL_frac нелинейна и требует экстраполяции.

Результат: RUL работает внутри известного распределения — 0.802, или 12.96 цикла ошибки. Ёмкость — 0.758. Напряжение — 0.048: дисперсию MLP не объясняет, и улучшение подгонкой не проводилось.

Открытым осталось главное: RUL_frac — это интерполяция внутри известного набора батарей, а не обобщаемость на любые режимы эксплуатации. И на двух задачах из трёх рабочая модель — не нейросеть, а линейная регрессия.
