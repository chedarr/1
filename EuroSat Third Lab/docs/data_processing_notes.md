# Лаба №3 (EuroSAT): обработка данных

Документ фиксирует, что именно сделано на этапе подготовки данных, какие решения приняты и какие проверки пройдены. Модель, baseline, абляции и отчёт — следующие этапы.

## 1. Окружение

| Параметр | Значение |
|---|---|
| ОС | Windows |
| Python | 3.13.15 |
| TensorFlow | 2.20.0 (CPU-сборка, `is_cuda_build: False`) |
| GPU | `[]` — не используется |
| `USE_GPU` | `False` |
| `MIXED_PRECISION` | `False` |
| Threading | `INTRA_OP_THREADS=6`, `INTER_OP_THREADS=1` |
| CPU | AMD Ryzen 5 3600, 6 ядер / 12 потоков |
| RAM | 15.93 ГБ |

Официальной GPU-сборки TensorFlow для Windows нет; WSL2 в рамках лабы не настраивался. Отсюда CPU-режим и упрощённая архитектура на следующем этапе — это ограничение среды, а не подгонка.

## 2. Источник данных

TFDS `eurosat/rgb`, версия 2.0.0: 27 000 снимков Sentinel-2, `(64, 64, 3)`, `uint8`, 10 классов.

Официальный билдер TFDS скачивает `EuroSAT.zip` с `madm.dfki.de`, который в этой сети недоступен (connect timeout). Использован официальный архив с Zenodo (record 7711810):

- `EuroSAT_RGB.zip`, 94 658 721 байт;
- md5 `f46e308c4d50d4bf32fedad2d3d62f3b` — совпал с опубликованным;
- архив распакован локально в `data/raw/eurosat_rgb/EuroSAT_RGB/<Class>/<Class>_<n>.jpg`;
- TFDS-датасет собран локально тем же билдером `eurosat/rgb` (подменён только шаг скачивания), после чего `tfds.load('eurosat/rgb', download=False)` работает без сети.

Лицензия: MIT (Zenodo), исходные снимки Sentinel-2 — Copernicus Sentinel Data Terms.

Отклонённые альтернативы:

- `eurosat/all` (13 каналов, `EuroSAT_MS.zip`, ~2.07 ГБ) — для RGB-постановки не нужен, дороже по диску и времени;
- Kaggle-копия — та же упаковка EuroSAT, дополнительных данных не даёт.

## 3. Проверки целостности

| Проверка | Результат |
|---|---|
| md5 архива | совпал |
| Число JPEG | 27 000 |
| Битые файлы (PIL `verify`, размер 64×64, режим RGB) | 0 |
| Уникальные хэши содержимого | 27 000 |
| Группы дубликатов | 0 |
| TFDS `num_examples` | 27 000 |
| Число классов | 10 |

Распределение по классам: AnnualCrop 3000, Forest 3000, HerbaceousVegetation 3000, Highway 2500, Industrial 2500, Pasture 2000, PermanentCrop 2500, Residential 3000, River 2500, SeaLake 3000. Отношение max/min = 1.5 — фиксируется, данные не выравниваются.

Возможное перекрытие: EuroSAT нарезан из более крупных сцен Sentinel-2, но идентификатор сцены в датасете не сохраняется, поэтому пересечение по исходной сцене между split проверить нельзя. Это ограничение источника, а не сплита; отмечено в `data_check.json`.

## 4. Split

Стратифицированный 70/15/15 по 10 классам, `seed=42`:

| split | снимков | доля |
|---|---|---|
| train | 18 900 | 0.700 |
| val | 4 050 | 0.150 |
| test | 4 050 | 0.150 |

Доли классов внутри каждого split отличаются от глобальных не более чем на 0.005 (проверка `check_stratification`). Пересечение индексов между split пустое. В `split_info.json` хранятся индексы снимков (0…26999), `class_id` и `split`; абсолютных путей нет.

## 5. Нормализация

Среднее и стандартное отклонение по каналам посчитаны **только по train**:

| канал | mean | std |
|---|---|---|
| R | 86.7113 | 51.9732 |
| G | 97.0472 | 35.1232 |
| B | 102.6883 | 29.6817 |

Значения — в шкале 0…255. К val и test применяются эти же статистики без пересчёта: иначе получилась бы leakage. Сохранено в `normalization_stats.json` (`source_split: train`, `n_pixels`).

## 6. Augmentation

Только на train: `RandomFlip("horizontal")`, `RandomRotation(0.05)`, `RandomZoom(0.1)`. Val и test подаются без изменений. Факт «только train» зафиксирован в `leakage_check.json` и проверяется тестом.

## 8. Ограничения этапа

- Данные хранятся в `uint8` до батча: 27 000 × 64 × 64 × 3 ≈ 316 МиБ в памяти, в `float32` было бы ≈ 1.3 ГБ.
- Перекрытие по исходной сцене не проверяемо (см. §3).
- Дисбаланс 1.5× не выравнивался; `class weights` — решение этапа модели.
- Baseline, абляции и метрики на этом этапе не считаются.
