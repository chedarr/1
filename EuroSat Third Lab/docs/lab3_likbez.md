# Ликбез: как понять лабораторную №3 (EuroSAT, CNN)

## 1. О чём эта работа

Есть 27 000 маленьких спутниковых снимков (64×64 пикселя). Каждый — кусок земной поверхности.
Надо научиться по картинке говорить, что там: лес, поле, город, вода, дорога и так далее — всего
10 классов.

Задача называется **многоклассовая классификация изображений**. Решается свёрточной нейронной
сетью (`CNN`, convolutional neural network). Сеть не получает готовых признаков — она учит их
сама из пикселей.

Главная метрика — **macro-F1**. Почему не accuracy — разберём в §4.

## 2. Термины

| Термин | Что это простыми словами |
|---|---|
| `accuracy` | Доля верных ответов. 0,9 = 90 снимков из 100 угаданы. |
| `precision` | Из тех, кого модель назвала классом X, сколько действительно X. «Точность попадания». |
| `recall` | Из всех настоящих X, сколько модель нашла. «Полнота охвата». |
| `F1` | Среднее гармоническое precision и recall. Одно число вместо двух. |
| `macro-F1` | F1, посчитанный по каждому классу отдельно, затем усреднённый. Каждый класс весит одинаково. |
| `confusion matrix` | Таблица 10×10: строки — истинные классы, столбцы — предсказанные. Диагональ — верные ответы. |
| `baseline` | Простая модель для сравнения: «а лучше ли сложная?». |
| `majority` | Всегда отвечает самым частым классом. |
| `random` | Отвечает случайно, равновероятно. |
| `HOG` | Histogram of Oriented Gradients — ручное описание картинки: где и в каком направлении идут границы. |
| `logreg` | Логистическая регрессия — линейный классификатор поверх признаков. |
| `split` | Разбиение данных на train / val / test. |
| `train` | Часть, на которой сеть учится (18 900 снимков). |
| `val` | Часть, по которой следят за обучением и выбирают эпоху (4 050). |
| `test` | Часть, по которой считают финальные метрики (4 050). |
| `epoch` | Один полный проход по всем train-снимкам. |
| `batch` | Порция снимков, после которой обновляются веса (у нас 64). |
| `augmentation` | Искусственные искажения train-снимков: отражение, поворот, зум. |
| `early stopping` | Остановка обучения, когда val_loss перестаёт улучшаться. |
| `patience` | Сколько эпох подряд разрешено не улучшаться, прежде чем остановиться. |
| `checkpoint` | Сохранение весов лучшей эпохи на диск. |
| `overfitting` | Переобучение: на train сеть отвечает всё лучше, на val — всё хуже. |
| `leakage` | Утечка: информация из test попала в обучение. Метрики после этого завышены. |

## 3. Что было сделано по шагам

### Шаг 1. Данные

Скачан архив EuroSAT RGB (94 658 721 байт, md5 `f46e308c…62f3b`). Внутри 27 000 JPEG.
Проверено: все 64×64, все RGB, битых нет, дубликатов по md5 нет.

Классы неравномерны: от 2 000 (`Pasture`) до 3 000 (`AnnualCrop`, `Forest`, `SeaLake` и др.).
Отношение 1,5× — это мягкий дисбаланс, но достаточный, чтобы accuracy и macro-F1 разошлись.

### Шаг 2. Split

70/15/15 со стратификацией: 18 900 / 4 050 / 4 050. Стратификация значит, что доли классов
в train, val и test одинаковые. Все индексы сохранены в `split_info.json`, seed = 42.
Пересечений между частями нет.

### Шаг 3. Нормализация

Считаем среднее и стандартное отклонение **только по train**: mean ≈ [86,7; 97,0; 102,7],
std ≈ [52,0; 35,1; 29,7]. Потом применяем эти же числа к val и test.

Почему только по train: если считать по всем данным, в нормализацию просочится информация
из test — это классическая ошибка, из-за которой метрика завышается.

### Шаг 4. Augmentation

Только на train: горизонтальное отражение, поворот ±5%, масштаб ±10%. Смысл — показать сети
те же объекты в чуть других условиях и снизить переобучение. На val и test искажений нет:
там мы хотим измерять, а не тренировать.

### Шаг 5. Модель

CNN из трёх свёрточных блоков. Каждый блок: `Conv2D` → `BatchNorm` → `ReLU` → `MaxPooling2D`.
Дальше `Flatten` → `Dense(128)` → `Dropout(0.5)` → `Dense(10)` с `softmax`.

Всего **549 626** параметров. Это очень небольшая сеть: у ResNet-50 их 25 миллионов.

### Шаг 6. Обучение

`Adam`, learning rate 0,001, `batch_size=64`, loss — `sparse_categorical_crossentropy`.
Максимум 20 эпох, `EarlyStopping` по `val_loss` с `patience=3`, `restore_best_weights=True`.

### Шаг 7. Первый результат — и сюрприз

Метрики на test: **accuracy 0,6899, macro-F1 0,6703**. Обучение остановилось на 5-й эпохе
и вернуло веса 2-й эпохи: там val_loss был минимальным (0,9217), а потом вырос.

Стало понятно, что `patience=3` — очень жёсткий протокол: сеть просто не успела доучиться.

### Шаг 8. Контрольный прогон

Изменены **только** два параметра: `patience` 3 → 50 и `epochs` 20 → 50. Всё остальное — та же
архитектура, тот же seed, тот же split, та же нормализация, тот же augmentation.

Результат на test: **accuracy 0,9079, macro-F1 0,9055**. Лучшая эпоха — 26-я из 50.

## 4. Цифры и что они значат

| Модель | accuracy | macro-F1 |
|---|---|---|
| majority | 0,1111 | 0,0200 |
| random | 0,0970 | 0,0968 |
| HOG + logreg | 0,5570 | 0,5397 |
| CNN, patience = 3 | 0,6899 | 0,6703 |
| **CNN, patience = 50** | **0,9079** | **0,9055** |

Что видно из таблицы:

- **majority** даёт accuracy 0,1111, потому что самый частый класс — это 11% данных.
  Но macro-F1 = 0,0200: девять классов из десяти не предсказываются вообще.
  Это и есть ответ на вопрос «почему accuracy обманчива».
- **random** даёт 0,0970 — примерно 1/10, как и ожидалось.
- **HOG + logreg** — 0,5570. Это уже не угадывание: ручные признаки работают.
- **CNN** — 0,9079. Разрыв с HOG больше 35 процентных пунктов.

Почему главная метрика macro-F1: при дисбалансе accuracy можно поднять, просто лучше
предсказывая крупные классы. macro-F1 считает каждый класс равным, поэтому «провал» редкого
класса сразу виден.

## 5. Что получилось и почему

Три главных факта.

1. **Данные и разбиение — чистые.** Нет пересечений, нет дубликатов по md5, нормализация
   не подглядывает в test.

2. **Основной прирост дал не «более умный» алгоритм, а длительность обучения.** Тот же код,
   та же сеть, те же данные: 0,6899 против 0,9079. Разница — 21,8 процентного пункта.

3. **Слабые классы остались слабыми.** `PermanentCrop` — F1 0,798, `Pasture` — 0,879.
   Основная ошибка: `PermanentCrop` → `HerbaceousVegetation` (63 снимка). Оба класса —
   растительность, различие в геометрии полей, а на 64×64 пикселях её видно плохо.

## 6. Спорные места

### (а) 0,9079 — это много?

Для 10 классов и 4 050 тестовых снимков — да, это высокий результат. Но:
тест использовался дважды (сначала для базового прогона, потом для контрольного), поэтому
он не полностью «слепой». И повторных прогонов с другими seed нет — значит, нет и разброса.

Честная формулировка: «0,9079 на одном прогоне с seed 42; доверительный интервал не оценивался».

### (б) Почему нельзя сказать «архитектура способна на большее»?

Потому что менялся только протокол остановки. Архитектура, learning rate, augmentation —
всё то же. Чтобы утверждать что-то про архитектуру, нужны отдельные эксперименты:
глубина, ширина, learning rate schedule, абляция augmentation.

### (в) 55 почти-дубликатов — это утечка?

Не доказано, но и не опровергнуто. Все 55 пар — класс `SeaLake`, MAD < 5 (пиксели почти
совпадают), но md5 у файлов разные. Это могут быть одни и те же участки воды после разного
сжатия, а могут — соседние участки одной сцены. В датасете нет `scene_id`, поэтому отличить
невозможно.

Что сделано: пары найдены, посчитаны, вынесены в `overlap_probe.json` и на рисунок.
Метрики `SeaLake` (F1 0,980) стоит считать оптимистичными.

### (г) Почему `patience=3` вообще дал такой плохой результат?

Потому что val_loss сильно колебался: 1,1493 → 0,9217 → 1,2365. После второго значения
три эпохи подряд улучшения не было — сработал счётчик. Сеть вернулась к весам 2-й эпохи,
когда она ещё не выучила признаки.

Это не баг, а свойство протокола: `patience=3` слишком мал для этой задачи.

## 7. Что сказать преподавателю

Короткая версия:

> Данные проверил: 27 000 снимков, 10 классов, split 70/15/15 стратифицированный, утечек нет.
> Нормализация только по train, augmentation только на train. CNN с нуля, 549 626 параметров.
> Базовый протокол с patience = 3 дал 0,6899 accuracy и 0,6703 macro-F1 — сеть остановилась
> на 5-й эпохе. Контрольный прогон с patience = 50 дал 0,9079 и 0,9055. Baseline HOG + logreg —
> 0,5570. Главное ограничение: в датасете нет scene_id, поэтому пересечение по сцене исключить
> нельзя; нашёл 55 почти-дубликатов в SeaLake.

## 8. Вопросы, которые могут задать

**— Почему macro-F1, а не accuracy?**
Классы несбалансированы (1,5×). accuracy поощряет модель, которая хорошо работает на крупных
классах и игнорирует мелкие. macro-F1 каждому классу даёт равный вес.

**— Почему нормализация только по train?**
Иначе среднее и std «знают» про test, и метрика перестаёт быть честной. Это leakage.

**— Зачем augmentation, если снимки и так разные?**
Чтобы сеть не запоминала конкретные снимки. Отражение и поворот не меняют класс, но меняют
пиксели — это бесплатная дополнительная вариативность.

**— Почему сеть переобучается после 26-й эпохи?**
549 тысяч параметров на 18 900 снимков — вполне достаточно, чтобы запомнить train.
val_loss начинает расти, train loss падает. Checkpoint спасает: сохраняются веса 26-й эпохи.

**— Что бы вы сделали дальше?**
Три вещи: (1) learning rate schedule или более сильная регуляризация; (2) повторные прогоны
с разными seed для оценки разброса; (3) проверка на 128×128, чтобы лучше разделить
`PermanentCrop` и `HerbaceousVegetation`.

**— Почему HOG + logreg так плохо?**
HOG описывает только направления границ. У воды и леса текстура богатая — работает.
У полей и пастбищ текстура похожа, а различие в мелкой геометрии — HOG её теряет.
