# Лабораторная №2 — ADAPT: бинарная классификация «норма / отказ»

Проект обработки телеметрии спутника ADAPT: по окну телеметрии определяется,
находится ли система в норме или в состоянии отказа.

## Задача

| Параметр | Значение |
|---|---|
| Тип | бинарная классификация |
| Целевая переменная | `fault` (0 — норма, 1 — отказ) |
| features (признаки) | 1620 (81 сенсор × 20 шагов) |
| Train | 204 окна, 12 экспериментов |
| Test | 62 окна, 4 эксперимента |
| Метрики | accuracy (доля верных ответов), precision (точность по отказам), recall (полнота), F1 (F-мера); threshold (порог решения) по валидации |
| Сравнение | MLP против baseline (постоянные ответы, логистическая регрессия) и одиннадцати конфигураций: базовая A и десять наборов улучшений B–K |
| Честная оценка | LOEO (leave-one-experiment-out) на всех 16 записях, без участия в выборе |
| Отчёт | HTML |

Разделение на Train и Test выполнено **по экспериментам** — окна одного
эксперимента не попадают одновременно в обе выборки.

## Воспроизводимость

* `seed = 42` фиксируется для `random`, `numpy` и `tensorflow`;
* в оценке LOEO (leave-one-experiment-out) каждому фолду назначается своё зерно
  (`42 + номер фолда`), поэтому повторный прогон даёт те же числа;
* версии библиотек зафиксированы в `requirements.txt`;
* сетевые обращения не используются: только локальные данные и локальные
  библиотеки.

## Результаты (test: 4 эксперимента, 62 окна)

| Модель | threshold | accuracy | precision | recall | F1 |
|---|---|---|---|---|---|
| Итоговая нейронная сеть | 0.395 | 0.903 | 1.000 | 0.812 | **0.897** |
| Нейронная сеть до улучшений | 0.500 | 0.806 | 1.000 | 0.625 | 0.769 |
| Модель из первого отчёта | 0.500 | 0.694 | 0.810 | 0.531 | 0.642 |
| Логистическая регрессия | 0.348 | 0.726 | 1.000 | 0.469 | 0.638 |
| Постоянный ответ «отказ» | — | 0.516 | 0.516 | 1.000 | 0.681 |
| Постоянный ответ «норма» | — | 0.484 | 0.000 | 0.000 | 0.000 |

recall — с 0.531 до 0.812, F1 — с 0.642 до 0.897, число пропущенных отказов
сократилось с 12 до 6. threshold выбран **только по валидации**; test в выборе
конфигурации и threshold не участвовал.

CV (cross-validation) по экспериментам внутри обучающей выборки (5 фолдов) даёт
F1 0.794 ± 0.179 — ниже, чем на test, то есть четыре test-эксперимента оказались
для модели скорее удачными. Разброс по test-экспериментам велик: F1 от 0.400
до 1.000. Именно разброс, а не среднее, описывает поведение модели.
Подробности и графики — в `reports/lab2_report.html`.

> Робастная оценка — 0.75 ± 0.33 (LOEO, threshold 0.5); 0.897 — верхняя граница
> на удачном test из 4 экспериментов; главное ограничение — нестабильность между
> экспериментами.

## Честная оценка на всех 16 экспериментах

Число 0.897 на test получено всего на четырёх записях. Чтобы измерить разброс по всем
записям, проведена оценка **LOEO (leave-one-experiment-out)**: каждая из 16 записей по очереди
исключается, сеть обучается на остальных пятнадцати, а threshold подбирается на одном
эксперименте, отведённом внутри обучающей части. Расчёт не участвует в выборе модели и
threshold — только измеряет устойчивость.

| Показатель | Среднее ± отклонение | Минимум | Максимум |
|---|---|---|---|
| F1 (tuned threshold) | 0.642 ± 0.406 | 0.000 | 1.000 |
| **F1 (threshold 0.5)** | **0.752 ± 0.329** | 0.000 | 1.000 |
| recall (threshold 0.5) | 0.766 ± 0.345 | 0.000 | 1.000 |
| precision (threshold 0.5) | 0.756 ± 0.333 | 0.000 | 1.000 |
| accuracy (tuned threshold) | 0.786 ± 0.216 | 0.355 | 1.000 |

Объединённый расчёт по всем 266 окнам шестнадцати записей даёт F1 0.748 при recall
0.652 и precision 0.878. Пять фолдов из шестнадцати дали F1 ровно 1.000, пять — ниже
0.5; промежуточных значений мало.

> Итоговая оценка: исходный test дал **0.897**, оценка LOEO по 16 экспериментам —
> **0.75 ± 0.33** (или **0.64 ± 0.41** при tuned threshold) при разбросе от
> 0.000 до 1.000. Число на test оптимистично: оно получено на четырёх записях и
> о разбросе не говорит ничего.

Отдельный вывод — про threshold: подобранный по **одному** контрольному
эксперименту, сам вносит разброс: в двух фолдах он увёл решение к краю распределения
и превратил безупречное разделение классов в F1 0.091 и 0.000 там, где обычный
threshold 0.5 давал 1.000 и 0.615. Поэтому сводка при threshold 0.5 устойчивее
подобранной.

Осторожность с метрикой: постоянный ответ «отказ» даёт F1 0.681 при precision 0.516,
поэтому F1 оценивается только вместе с precision, а threshold ограничен снизу
требованием precision не ниже 0.70.

### От чего зависит нестабильность

Диагностика LOEO показала, что доступные характеристики экспериментов (доля отказов,
позиция первого отказа, разброс сенсоров, dist_to_train) не объясняют разброс F1:
максимальный |ρ| = 0.350 (p = 0.183), остальные |ρ| ≤ 0.114, все p > 0.05. При n = 16
мощность теста низкая, поэтому отсутствие значимости не доказывает отсутствия связи —
но и не даёт оснований её утверждать. Разброс указывает на нехватку данных, а не на
найденную закономерность.

Только на 12 обучающих записях связь F1 с dist_to_train сильнее (ρ = −0.713, p = 0.009),
но это подмножество тех же наблюдений и без поправки на множественные сравнения
доказательством не является.

## Что дало прирост

Проверено десять наборов улучшений (B–K) относительно базовой конфигурации A; всего
одиннадцать конфигураций. Прирост считается от базовой модели (F1 на test 0.769);
знак «−» означает, что приём навредил.

| Набор | Что добавлено | ΔF1 (test) | ΔF1 (val) |
|---|---|---|---|
| `D_ёмкость` | BatchNorm, L2, Dropout, слои 128–64–32 | **+0.127** | +0.039 |
| `E_ёмкость_веса` | то же плюс class weights | +0.120 | +0.020 |
| `B_веса_классов` | class weights | +0.067 | +0.019 |
| `C_нормализация` | BatchNorm и L2 | +0.046 | +0.031 |
| `H_шаг_5` | class weights и более мелкий шаг окон | +0.023 | −0.048 |
| `I_смещения` | class weights и смещённые окна | +0.023 | +0.008 |
| `G_признаки` | статистики и разности | +0.015 | −0.071 |
| `J_комбинация` | всё сразу | −0.049 | −0.047 |
| `K_шаг_5_базовая` | базовая сеть на окнах с шагом 5 | −0.075 | −0.002 |
| `F_аугментация` | шум, сдвиг, масштаб | −0.191 | −0.143 |

Разложение прироста: пересмотр порядка обучения поднял F1 с 0.642 до 0.769
(+0.128), смена архитектуры добавила ещё +0.127, а подбор threshold на базовой
архитектуре не добавил ничего. Итог: F1 0.897.

Про шаг окон отдельно. Уменьшение шага с 10 до 5 увеличивает число обучающих окон
с 204 до **401** (тот же набор данных лежит в `data/processed/adapt_train_step5.parquet`),
но прироста не даёт: по валидации F1 0.827 против 0.829 у базовой модели, на test
0.694 против 0.769. Причина в том, что соседние окна с частой сеткой почти дублируют друг
друга и новой информации не несут. Test-окна при этом не пересобирались и остались на
шаге 10, поэтому исходный test сохранён и сравнение остаётся честным.

Отдельный урок про threshold. В прежнем порядке обучения контроль состоял из двух
экспериментов, на которых модель разделяла классы идеально; подобранный по такому
контролю threshold 0.926 на test давал F1 0.615 — хуже обычного 0.5. Подбор threshold
полезен ровно настолько, насколько представителен контроль; оценка LOEO
подтверждает это на всех шестнадцати записях.

## Технические заметки

* Обучение выполняется на CPU: сборка TensorFlow для Windows не видит GPU,
  поэтому лимиты видеопамяти не применяются, а параллелизм ограничен числом
  потоков процессора.
* Графики и отчёт собираются офлайн, без внешних ресурсов.
