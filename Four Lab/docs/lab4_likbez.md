# Ликбез: лабораторная работа №4 — многомерный прогноз ряда GOCE с помощью LSTM

## 1. О чём эта работа

Есть ряд измерений спутника GOCE с шагом 10 минут: напряжение батареи и четыре связанные величины (ток заряда, ток разряда, две температуры). Нужно по последним 24 часам истории предсказать напряжение на следующие 24 часа — сразу 144 значения вперёд.

Это **multivariate forecasting (многомерный прогноз)**: на входе не один ряд, а пять, и все они подаются в модель одновременно. Главный вопрос работы — даёт ли добавление четырёх каналов к одному измеримое улучшение и обыгрывает ли рекуррентная сеть честные baseline.

## 2. Термины

| Термин | Что значит |
|---|---|
| `multivariate forecasting` | прогноз, в котором на входе несколько рядов сразу, а не один |
| `lookback` (окно истории) | сколько шагов назад смотрит модель — 144 шага = 24 часа |
| `horizon` (горизонт) | сколько шагов вперёд предсказывается — 144 шага = 24 часа |
| `direct multi-step` | модель выдаёт все шаги горизонта одним выходом (здесь — 144 числа сразу) |
| `recursive multi-step` | модель предсказывает шаг за шагом и подаёт свои же предсказания обратно на вход |
| `stride` (шаг окон) | сдвиг между началами соседних окон — 12 шагов = 2 часа |
| `timestamp` | момент измерения; здесь — индекс ряда, а не отдельная колонка |
| `value_mean` | среднее значение канала за 10-минутный интервал — то, что подаётся в модель |
| `value_count` | число измерений внутри интервала; 0 означает «измерений не было» |
| NaN | пропуск: измерения нет |
| `split` | разбиение ряда на train / val / test |
| `baseline` | простой метод-эталон, с которым сравнивают модель |
| `persistence` (naive forecast) | «завтра будет как сейчас»: последнее значение повторяется на весь горизонт |
| `constant` | прогноз одним числом — средним по train на все шаги и все окна |
| `MAE` (mean absolute error) | средняя абсолютная ошибка, в тех же единицах, что и напряжение (В) |
| `RMSE` (root mean squared error) | корень из средней квадратичной ошибки; сильнее штрафует крупные промахи |
| `R²` (coefficient of determination) | доля разброса, объяснённая моделью; 1 — идеал, 0 — уровень «среднего», меньше 0 — хуже среднего |
| `skill score` | 1 − MAE модели / MAE baseline; 0 — как baseline, больше 0 — лучше |
| `ΔMAE` | разность MAE с опорной строкой таблицы; отрицательное значение означает улучшение |
| `leakage` (утечка) | информация из будущего или из test попала в обучение |
| `scaler` / `StandardScaler` | приведение признаков к нулевому среднему и единичной дисперсии; обучается **только** на train |
| `LSTM` (long short-term memory) | рекуррентный слой, который хранит состояние и умеет забывать лишнее |
| `GRU` (gated recurrent unit) | упрощённый рекуррентный слой с двумя вентилями вместо трёх |
| `Dense` | полносвязный слой; здесь строит выход на 144 шага |
| `dropout` | случайное отключение части нейронов при обучении — регуляризация |
| `BatchNorm` | нормализация активаций по батчу; стабилизирует и ускоряет обучение |
| `L2` | штраф за большие веса (weight decay) — ещё один способ регуляризации |
| `Adam` | адаптивный оптимизатор, который подбирает шаг для каждого веса |
| `MSE` (mean squared error) | средняя квадратичная ошибка — функция потерь при обучении |
| `EarlyStopping` | остановка обучения, когда `val_loss` перестаёт улучшаться `patience` эпох подряд |
| `permutation importance` | важность канала: насколько вырастает MAE, если перемешать его значения |
| `seed` | зерно генератора случайных чисел; фиксирует инициализацию и разбиение |

## 3. Откуда данные

**Источник.** GOCE — спутник Европейского космического агентства (ESA), работавший в 2009–2013 годах и измерявший гравитационное поле Земли. Вместе с научными измерениями он передавал телеметрию служебных систем, в том числе батарейной подсистемы. Именно эта телеметрия и используется.

**Что лежит в файлах.** Датасет содержит статистики 327 каналов, посчитанные на 10-минутных интервалах. В работе используются только пять батарейных каналов:

| Канал | Что измеряет | Роль |
|---|---|---|
| `PHT10080` | ток заряда | признак |
| `PHT10100` | ток разряда | признак |
| `PHT10180` | напряжение батареи | **целевая** |
| `PHT10260` | температура TMP_1 | признак |
| `PHT10300` | температура TMP_2 | признак |

Каждый parquet-файл — это таблица `239 616 × 11`: одна строка на 10-минутный интервал и одиннадцать колонок-статистик.

| Колонка | Что содержит |
|---|---|
| `value_min` | минимум внутри интервала |
| `value_q05` | 5-й процентиль |
| `value_q95` | 95-й процентиль |
| `value_max` | максимум внутри интервала |
| `value_mean` | среднее внутри интервала |
| `value_median` | медиана |
| `value_std` | стандартное отклонение |
| `value_skew` | асимметрия распределения |
| `value_sum` | сумма измерений |
| `value_last` | последнее измерение в интервале |
| `value_count` | число измерений в интервале |

**Почему только `value_mean`.** Одиннадцать колонок — это не одиннадцать датчиков, а одиннадцать агрегатов одного и того же сигнала за те же 10 минут. Если подать их все, модель получит многократно продублированную информацию: `value_min`, `value_max`, `value_median` и `value_mean` описывают один и тот же отрезок, `value_sum` растёт вместе с `value_count`, а `value_last` почти повторяет соседний шаг. Поэтому оставлено одно среднее — самая устойчивая к выбросам сводка интервала. Кроме того, производные агрегаты (`value_last`, `value_sum`, `value_count`, `value_min`, `value_max`) прямо запрещены в признаках и проверяются отдельным скриптом: они легко превращаются в утечку.

**Про `value_count = 0`.** Ноль в этой колонке означает «за интервал не пришло ни одного измерения», а не «измеренное значение равно нулю». Напряжение 0 В у работающего спутника — физически бессмысленная величина, и трактовать пропуск как ноль нельзя: это создало бы ложные провалы ряда. В `value_mean` такие интервалы приходят как NaN, и дальше они обрабатываются как пропуски.

**Индекс и пропуски.** Индекс — `timestamp` с регулярным шагом 10 минут. Всего 239 616 интервалов; после удаления строк с NaN остаётся 231 194. Пропуски составляют **3,515 %** (8 422 строки). Почти все они собраны в три длинные серии; самая большая — **7 270 шагов = 50,5 суток** (июль–август 2010). Короткие пропуски до 6 шагов (1 час) удаляются построчно, длинные серии считаются разрывами: окна, которые их пересекают, выбрасываются целиком, потому что склеивать «до» и «после» разрыва нельзя — между ними пропущены полтора месяца.

## 4. Почему split хронологический, а не по группам

В лабораторной работе №1 split делался по батареям (`GroupShuffleSplit`): там строки одной батареи почти идентичны, и случайное разбиение по строкам разнесло бы почти одинаковые наблюдения в train и test. Разбиение по группам решало эту проблему.

Здесь групп нет. Есть один непрерывный временной ряд, и единственный корректный способ его делить — **по времени**: первые 70 % — train, следующие 15 % — val, последние 15 % — test. В числах: `[0; 161 836)`, `[161 836; 196 515)`, `[196 515; 231 194)`.

Причина проста: при перемешивании модель увидит «завтра» в train, а тестироваться будет на «вчера». Это **leakage (утечка) из будущего** — самая частая ошибка в задачах прогноза. Ошибка на test после такой утечки падает не потому, что модель хороша, а потому, что она уже видела ответы.

Есть и второй уровень аккуратности: окна не должны пересекать границы сплитов. Окно — это 144 шага истории плюс 144 шага горизонта, то есть 288 последовательных точек. Если начало окна попадает так, что горизонт заходит в val или test, окно выбрасывается. Всего из-за границ отброшено 48 окон; ещё 103 окна пропущены из-за NaN и разрывов. Итог: 13 384 окна в train, 2 842 в val, 2 866 в test. `scaler` при этом обучается только на train и применяется к val/test без пересчёта.

## 5. Как устроен процесс

### 5.1. Данные

Пять parquet-файлов соединяются по `timestamp` (inner join), из каждого берётся только `value_mean`. Получается 239 616 строк; после удаления NaN остаётся 231 194. Три длинные серии пропусков (включая разрыв 50,5 суток) помечаются как разрывы, короткие пропуски удаляются.

### 5.2. Признаки

Вход модели — окно `144 × 5`: 24 часа истории по пяти каналам. Выход — 144 значения целевой, то есть 24 часа напряжения. Шаг между окнами — 12 (2 часа). Признаки и целевая масштабируются `StandardScaler`, обученным только на train; обратное преобразование делается до расчёта метрик, поэтому все MAE и RMSE — в вольтах.

### 5.3. Модель

Базовая конфигурация A: `LSTM(64)` → `Dense(32)` → `Dense(144)`, `dropout` 0,1, `Adam` с learning rate 0,001, `MSE` как функция потерь, `EarlyStopping` с `patience` 8 и потолком 30 эпох. Лучшая конфигурация D: `LSTM(128)` → `Dense(64)` → `Dense(144)`, `dropout` 0,2. Обе — **direct multi-step**: все 144 шага выдаются одним проходом, без рекурсии.

### 5.4. Split

Хронологический 70/15/15 без перемешивания. Окна, пересекающие границы сплитов, отбрасываются. Нормализация — только по train. Проверка утечек подтверждает: `scaler_fit_on_train_only = true`, `windows_cross_split_boundaries = false`, запрещённые колонки не используются.

### 5.5. Baseline

Три эталона на том же test: `persistence` (повтор последнего значения), `constant` (среднее train) и `linear` — `Ridge` с α = 1 на всех 720 лагах всех пяти каналов (5 × 144). Линейная модель — сильный baseline: она видит всю историю окна, но не умеет моделировать нелинейность.

### 5.6. Результат

Лучшая модель — D_большая: MAE **0,1906 В**, RMSE 0,3294 В, R² 0,777, skill score 0,718. Linear baseline — 0,2572 В, то есть модель лучше на 0,0666 В (25,9 % снижения MAE). Persistence — 0,6765 В, constant — 0,5040 В. Многомерная A (0,1985 В) лучше одномерной B (0,2215 В) на 0,0230 В (10,4 %).

### 5.7. Ограничения

Один seed, разрыв 50,5 суток, сильное перекрытие окон при шаге 12, только 5 каналов из 327, обучение на CPU с потолком 30 эпох, direct multi-step без сравнения с recursive, permutation importance только для конфигурации A. Подробнее — в §9.

## 6. Цифры и что они значат

Метрики считаются на test в исходных единицах (вольты), по всем 144 шагам горизонта сразу.

| Модель | MAE, В | RMSE, В | R² | skill vs persistence |
|---|---|---|---|---|
| persistence | 0,6765 | 0,9665 | −0,921 | 0,000 |
| constant | 0,5040 | 0,7792 | −0,249 | 0,255 |
| linear (Ridge) | 0,2572 | 0,4400 | 0,602 | 0,620 |
| LSTM B (1 канал) | 0,2215 | 0,3612 | 0,732 | 0,673 |
| LSTM A (5 каналов) | 0,1985 | 0,3264 | 0,781 | 0,707 |
| LSTM D (большая) | 0,1906 | 0,3294 | 0,777 | 0,718 |

**Как читать.** `persistence` — нижняя планка: если модель не лучше «завтра как сейчас», она бесполезна. `constant` оказывается **лучше** persistence (0,5040 против 0,6765), и это важный сигнал: на 24-часовом горизонте простое повторение последнего значения систематически промахивается. `linear` — сильный baseline, он видит все 720 входных значений и задаёт высокую планку. LSTM обыгрывает и его, и все три эталона.

**Проценты.** 0,1906 В — это около 0,6 % от среднего напряжения 33,35 В. Для грубого прогноза приемлемо, для прецизионного — нет: абсолютная ошибка в 0,19 В на суточном горизонте заметна.

**Чего нельзя сравнивать.** MAE при горизонтах 144, 72 и 28 — это разные задачи. При horizon 72 MAE равен 0,1220 В, при horizon 28 — 0,0812 В, но эти числа не означают, что модель «стала лучше»: короче горизонт — меньше накопленная ошибка. Сравнивать можно только конфигурации с одинаковым горизонтом.

## 7. Почему многомерность помогает

Прямое сравнение: A (5 каналов) — MAE 0,1985 В, B (только целевая) — 0,2215 В. Многомерная модель лучше на 0,0230 В, это **10,4 % снижения MAE**. Различие больше порога 0,005 В, но получено на одном seed, поэтому речь о величине эффекта, а не о статистической значимости.

**Почему это работает.** Дополнительные каналы не заменяют напряжение, а дают контекст, которого нет в одном ряду:

- ток разряда `PHT10100` коррелирует с напряжением с коэффициентом **0,972** — почти линейная физическая связь;
- температуры `PHT10260` и `PHT10300` коррелируют с напряжением отрицательно (**−0,288** и **−0,286**): нагрев сопровождается просадкой;
- ток заряда `PHT10080` связан слабо (**0,096**), но полезен как индикатор режима.

По одним значениям напряжения трудно отличить «просадку из-за разряда» от «просадки из-за температуры». Два дополнительных измерения разделяют эти режимы, и модель точнее переносит суточный цикл на горизонт.

**Но есть важная поправка.** Permutation importance для конфигурации A показала, что главный предиктор — сама целевая: перемешивание `PHT10180` поднимает MAE на **+0,17915 ± 0,00221 В**. Разрядный ток, несмотря на корреляцию 0,972, даёт рост всего **+0,03014 ± 0,00075 В**, заряд — +0,06903, температуры — +0,01273 и +0,01148.

| Канал | ΔMAE при перестановке, В | std |
|---|---|---|
| `PHT10180` (напряжение, целевая) | +0,17915 | 0,00221 |
| `PHT10080` (ток заряда) | +0,06903 | 0,00059 |
| `PHT10100` (ток разряда) | +0,03014 | 0,00075 |
| `PHT10300` (TMP_2) | +0,01273 | 0,00036 |
| `PHT10260` (TMP_1) | +0,01148 | 0,00036 |

Вывод: шортката «предсказывать напряжение по току» нет — модель опирается прежде всего на историю напряжения. Многомерность полезна не потому, что ток подменяет целевую, а потому, что добавляет контекст режима и температуры.

## 8. Спорные моменты

### 8.1. Зачем LSTM, если linear baseline силён?

**Факт.** Linear baseline (Ridge на 720 лагах) даёт MAE 0,2572 В, LSTM — 0,1906 В. Модель лучше на 0,0666 В, это 25,9 % снижения MAE.

**Разбор.** Ridge уже видит всю историю окна и является сильным соперником: на коротких рядах линейная модель часто обыгрывает небольшую сеть. Но суточный цикл нелинеен — заряд и разряд меняют знак производной, а температура влияет не аддитивно. Линейная модель может описать только взвешенную сумму лагов; LSTM — переключаться между режимами.

**Вывод.** LSTM оправдана: она побивает не слабый, а сильный baseline. При этом разрыв 25,9 % — не приговор линейной модели, а мера того, сколько даёт нелинейность на этом ряде.

### 8.2. R² = 0,777 у LSTM — это хорошо?

**Факт.** Формально модель объясняет 77,7 % дисперсии напряжения на горизонте.

**Разбор.** R² считается по всем 144 точкам сразу, и дальние шаги «роняют» метрику сильнее, чем ближние: ошибка на 24-м часу больше, чем на первом. Отрицательный R² у persistence (−0,921) и constant (−0,249) — не признак «сломанной модели», а следствие узкой дисперсии целевой на горизонте: даже умеренная абсолютная ошибка оказывается больше разброса.

**Вывод.** R² = 0,777 — честная оценка, но читать её нужно вместе с MAE 0,1906 В. Одно число без другого здесь не интерпретируется.

### 8.3. Почему persistence хуже constant?

**Факт.** Persistence — MAE 0,6765 В, constant — 0,5040 В. Простейший «прогноз средним» лучше «прогноза последним значением».

**Разбор.** Persistence повторяет последнее значение на все 144 шага. За 24 часа напряжение успевает пройти суточный цикл заряда и разряда, поэтому копия систематически ошибается: в фазе разряда она завышает, в фазе заряда занижает. Constant тоже не различает режимы, но выбирает точку внутри диапазона и не «промахивается» так сильно в среднем.

**Вывод.** Для длинного горизонта persistence — плохой baseline. Его сила в том, что он задаёт нижнюю планку «наивного» прогноза; его слабость в том, что суточный цикл он игнорирует полностью.

### 8.4. Почему D_большая лучше A_базовой?

**Факт.** A: `LSTM(64)` → `Dense(32)` → `Dense(144)`, dropout 0,1, **24 752** параметра, MAE 0,1985 В. D: `LSTM(128)` → `Dense(64)` → `Dense(144)`, dropout 0,2, **86 224** параметра, MAE 0,1906 В. Улучшение — 0,0078 В.

**Разбор.** D больше по ёмкости в 3,5 раза и одновременно сильнее регуляризована. Улучшение нельзя приписать только dropout: изменились и размер слоёв, и регуляризация. Отдельно видно, что dropout полезен: конфигурация E0 (dropout 0) даёт 0,2014 В, то есть хуже A с dropout 0,1.

**Честная оговорка.** D обучалась все 30 эпох, `EarlyStopping` не сработал (лучшая эпоха — 28-я), поэтому её результат, скорее всего, ограничен потолком эпох, а не сошлась она. Улучшение 0,0078 В выше порога 0,005 В, но получено на одном seed. Корректная формулировка: размер и регуляризация должны расти вместе, а не «dropout 0,2 лучше dropout 0,1».

## 9. Ограничения

| Ограничение | Что ломается | Разрешимо на текущих данных |
|---|---|---|
| Один seed | разброс между запусками не измерен; различия меньше 0,005 В нельзя считать значимыми | да, 3–5 seed |
| Разрыв 50,5 суток | окна через разрыв выброшены, соседние окна могут быть нерепрезентативны | нет, это свойство данных |
| Перекрытие окон (шаг 12) | соседние окна делят 132 из 144 шагов истории; эффективная выборка меньше 13 384 | да, увеличить шаг |
| R² на длинном горизонте | метрика считается по всем 144 точкам сразу и не показывает, где именно модель ошибается | да, считать R² по шагам |
| Только 5 каналов из 327 | остальные каналы не использовались | да, расширить набор |
| CPU-only | обучение ограничено 30 эпохами и небольшими сетями | нет, GPU не виден |
| Direct multi-step | рекурсивный вариант не проверялся | да, сравнить на одном горизонте |
| Permutation importance только для A | для D и остальных конфигураций важность не считалась | да, повторить |

Отдельно стоит помнить: корреляция разрядного тока с напряжением 0,972 выглядит почти как утечка, но permutation importance показала, что это не шорткат — перестановка тока даёт +0,03014 В против +0,17915 В у самой целевой.

## 10. Что спросить у преподавателя

1. **Про многомерность.** Пять каналов лучше одного на 10,4 %, но permutation importance показала, что главный предиктор — сама целевая. Оправдано ли использовать пять каналов, или для этой задачи достаточно одного? *Обоснование:* эффект измерен, но его источник — контекст, а не замена целевой.*
2. **Про горизонт.** 144 шага (24 часа) — заявленный горизонт датасета, но MAE растёт с шагом. Корректно ли сравнивать MAE на 144 шагах с MAE на 28 шагах? *Обоснование:* это разные задачи, и в отчёте они разведены по разным таблицам.*
3. **Про baseline.** Linear (Ridge) — сильный эталон. Достаточно ли его, или стоит добавить gradient boosting, kNN и ансамбли по seed? *Обоснование:* один сильный baseline не закрывает вопрос о пределе качества.*
4. **Про разрыв 50,5 суток.** Это естественный пропуск телеметрии или ошибка выгрузки? Влияет ли он на репрезентативность test? *Обоснование:* разрыв — свойство данных, но его происхождение не проверено.*
5. **Про permutation importance.** Она проведена только для A. Стоит ли повторить для D_большая — лучшей модели? *Обоснование:* важность признаков может отличаться у более крупной сети.*
6. **Про direct multi-step.** Мы предсказываем все 144 шага сразу. Стоит ли сравнить с рекурсивным вариантом «шаг за шагом»? *Обоснование:* direct не накапливает ошибку, recursive использует свои предсказания как вход.*
7. **Про значимость различий.** Различия в 0,002–0,004 В между A, E, G находятся ниже порога 0,005 В. Нужно ли усреднение по 3–5 seed, чтобы называть такие различия реальными? *Обоснование:* один seed не даёт оценки разброса.*

## 11. Как объяснить вслух за две минуты

«У нас есть пятимерный ряд с шагом 10 минут: напряжение батареи GOCE, ток заряда, ток разряда и две температуры. Мы берём сутки истории и просим LSTM предсказать сутки вперёд — сразу 144 значения.

Ряд разбит по времени, 70/15/15, чтобы не было утечки из будущего. Нормализация обучена только на train. Сравниваем с тремя простыми методами: persistence, constant и Ridge по всем лагам.

Лучшая модель — D_большая, MAE 0,1906 В. Linear baseline — 0,2572 В, то есть модель лучше на 25,9 %. Persistence — 0,6765 В, constant — 0,5040 В. Пятиканальная модель лучше одноканальной на 10,4 %. Permutation importance показывает, что главный предиктор — история самого напряжения, а не ток: шортката нет.

Ограничения честные: один seed, разрыв 50,5 суток, перекрытие окон, только 5 каналов из 327 и обучение на CPU с потолком 30 эпох».
